**New regressions and contradictions**

**N01 — BLOCKER — The new settlement invariant and four-contributor oracle cannot both conserve chips.** §§4.3/13.1, L201/584–585; relates to S17/S18. Returning excess to stacks and also adding `returned` to the conservation equation counts it twice. With starting stacks and all-in contributions 50/100/200, settled stacks contain the 100 refund and pots contain 250: the specified equation gives 450 against starting 350. The added four-player case 50/100/200/200 totals 550; its pots are **200/150/200**, not 200/200/200. **Edit:** use `sum(remaining stacks) + unawarded pot chips + rake already collected = sum(start stacks)`. Returns/awards are transfers, never extra terms. Before a street settles, include live commitments exactly once rather than prematurely refunding a bet still awaiting a response. Correct the four-player oracle and assert the same invariant after each action and refund.

**N02 — BLOCKER — Dropping a folded bettor creates an impossible HU history.** §§1.2/4.3/6/10.2, L19/196/360/371/502–504. Three-way street: A bets 50, B calls 50, C raises to 150, A folds; B must act. The new projection removes A, adds 50 dead chips to the root and leaves **B Call, C Raise(150)**. Call is illegal at an unbet HU root; adding dead money cannot restore the missing facing wager. The mandatory reconstruction assertion fails even though §6 promises numeric approximate EV. Separately, §6's experimental multiway solve uses current pot/remaining stacks, conflicting with “every solve” being a street-root solve and with the only specified Solve builder. **Edit:** for phase 1, explicitly return UnsupportedHistory for a multiway-root projection that cannot reproduce the current legal state; do not promise unconditional numeric coverage. Defer general projection, or define and validate a separate approximation contract before admitting it. Give the outline-required experimental HU surrogate an explicit isolated synthetic-root contract with empty replay history and stated unconditioned ranges, retaining its separate display.

**N03 — MAJOR — Cache quality/labels use three incompatible notions of exactness.** §§2/5/10.4/13.1, L45/237/326/519–522/613–614; S09/S20. §2 requires equal inputs/no bucketing, while §10.4 calls up-to-1% SPR differences and small chip-rounding changes Exact. More concretely, §10.4 tests rounded `reached_bp`; an entry solved to a 100-bp target with actual exploitability 50.49 bp can display 50 and pass a new 50-bp request, contrary to the raw comparison rule. `0.5 * quantum / P` is a worst-case rounding bound, not the actual size deviation: it labels even an exactly representable half-pot bet at P=20. §5 also adds SprBucketed to every approximate hit, including a rounding-only hit. **Edit:** filter on saved raw exploitability/P against `target_bp / 10000`, calculate realized per-action size differences, and emit only the reasons actually incurred. Reconcile the declared Exact tolerance with the controlling outline; absent an authorized amendment, label non-equivalent reuse approximate or miss. Update all examples/tests together.

**N04 — MAJOR — Normalized cache lookup still selects a node using chip-valued paths, and its test prohibits navigable reuse.** §§4.5/10.4/13.1, L263/517–519/613; S05/S09. A stored path Bet(50), Call in a P=100 game corresponds to Bet(100), Call at P=200. Payload paths are Vec<Action> with chip amounts; §10.4 selects the node before specifying any path conversion. Literal comparison misses a supposedly equivalent scaled game. The test additionally requires check-prefix/changed-path misses, although the cache deliberately stores multiple actor-owned nodes and omits requested path from the key. **Edit:** define a normalized node-path identity or deterministic source-tree-to-query-tree node mapping before selection; apply it to every action-bearing path, including insertions and replay snapshots. Check and a different covered path select their own valid nodes; only absent/incompatible paths or wrong actor metadata miss. Test non-root 2× scaling, both actors and a cache hit subsequently used for replay.

**N05 — MAJOR — Bit-exact f32 hashing cannot satisfy the new arbitrary-rescaling test.** §§2/10.4/13.1, L52/517/592; S09. For f32 weights `[1, 0.003]`, the second value is approximately 0.003000000026. Multiplying both weights by f32(0.37), rounding, then dividing by the maximum yields approximately 0.003000000259. The hashes differ despite the test's required equality. “Any single weight change alters the hash” also needs an exception for a one-supported-combo range, whose positive magnitude is intentionally normalized away. **Edit:** retain exact normalized-bit matching, but require deterministic normalization and limit exact scale-invariance tests to transformations that preserve representable ratios, such as suitable powers of two. Treat rounded-ratio changes as misses. Do not add unapproved lossy range quantization merely to make the test pass.

**N06 — MAJOR — New snapshot rules discard known evidence and disable required prior-street translation.** §§5/9.1–9.3/10.4, L326/465/474–481/518; S15. A solve occurs before later actions; its tree need not contain a subsequently entered off-menu wager. The assertion that such actions “do not occur” is false. Requiring the snapshot to contain *every* eventual street action rejects its already valid prefix, so one missing continuation makes the entire street unconditioned, contradicting §13.1's pre-action-range fallback. Cache hits go straight to Final, while snapshot recording is specified only for worker ok/best_so_far results. Truncated exports intensify this problem. **Edit:** register validated cached and live solutions through the same snapshot path; distinguish active request identity from immutable snapshot provenance. Retain explicit solved-prefix/ancestry metadata, reuse covered prefixes, translate later off-menu prior-street actions per Outline §3, and stop only unavailable continuations with their reasons. State how a truncated export advertises covered paths. Do not erase all known conditioning because one descendant is absent.

**N07 — MAJOR — The new branch cap and node mixture are not a posterior distribution.** §8.4, L452–455; S12. The spec seeds branches with translation weights, but never defines the conditional branch weights used at a later decision. With initial weights 0.5/0.5 and observed likelihoods 0.9/0.1 for a given combo, those weights become 0.9/0.1 after conditioning, not 0.5/0.5. Multiplying the full sequence likelihood again at every action would also double-condition earlier observations. Keeping only four “heaviest” branches leaves dropped mass, tie-breaking and coverage unspecified; later “no silent renormalization” cannot resolve it. **Edit:** define per-combo branch posterior updates or the ratio of successive prefix likelihoods, and use the resulting posterior in current-node strategy/EV assembly. Define action-conditional EV weighting. At branch-budget overflow, preserve the pre-action posterior with an explicit approximation/fallback reason, or retain and account for a residual branch; do not silently discard mass.

**N08 — MAJOR — Added worker stages/events still encode unavailable measurements as measured zero and disagree on terminal payloads.** §§4.4/4.5/7/12, L220–235/257–274/281/293/395; S07/S20/S31. Building progress explicitly sends exploitability 0 before any measurement, while both progress types require a number. Pending/Unavailable equity still requires Exact/MonteCarlo metadata. The stop path emits `no_iteration`, absent from the failure-code list; tree_too_large requires estimate_bytes but the declared error payload has no field for it. Error is nested in SolveStatus in the sketch and a sibling field in the literal example, without a normative serialization rule. **Edit:** supply one tagged wire schema with optional/unmeasured accuracy, coherent result/error payloads and all failure codes/fields. Define cancellation outcomes in Building and Extracting, including shutdown/process death, and staging replacement/rejection. Specify that late Equity may enrich a Final of the same identity and that a later payload cannot replace Ready equity with Pending. Add the separate range-level mix/availability fields required by S19/S20.

**N09 — MAJOR — A common all-in call leaves the new hand lifecycle without a next state.** §4.3, L199; S30. After a short player's shove is called by a deeper player, exactly one survivor retains chips. “Two or more players not all-in” is false; “all remaining are all-in” is also false. Betting closes automatically, but neither declared transition applies, preventing completion/idle scheduling. Also, support for fewer than six dealt seats is added without a two-dealt-seat blind rule: the button must be SB in that case, which cannot follow the six-seat BTN→SB→BB assignment literally. **Edit:** after outstanding calls/refunds, finish as AllInRunout whenever no further betting is possible, even if one survivor retains chips. Either define occupied-seat and two-player blind/action order completely or restrict the supported dealt-seat counts explicitly; keep lookup mapping separate from actual rules.
