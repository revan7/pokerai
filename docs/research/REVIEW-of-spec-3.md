**New contradictions and ambiguities**

**P01 — BLOCKER — The engine materializer still disagrees with the pinned worker on facing-wager all-ins.** §§4.6/10.3/13.2, L343–350/569/711; N11/S25. The builder uses `max <= round(pot * threshold)` for opening/donk bets, but **`max <= prev + round(pot * threshold)` when facing a non-all-in wager**. It also clamps a listed amount before testing force-all-in. [Pinned construction](https://github.com/b-inary/postflop-solver/blob/9d1509fe5077d019825f833eed04b16d342dfda1/src/action_tree.rs#L543-L645).

Concrete counterexample: root P=100, effective stack=350, observed bet-to100, add threshold=1, force threshold=0, raise menu=2.5x. At the facing node, post-call pot=300, prev=100, max=350. The spec omits the jam because 350>300; the worker includes it because 350<=400. Raise250 does not repair that difference. The mandatory cross-check therefore produces `tree_mismatch` on a legal supported history. **Edit:** split the opening/facing rules, exclude raises against all-in, specify clamp-before-force order, and add this facing-node fixture beside the existing opening equality cases. This is a fixed backend contract, not a benchmark question.

**P02 — BLOCKER — Branch assembly silently drops unevaluated worlds, and branch evidence has no cross-actor transfer rule.** §§8.4/9.1–9.3/4.4, L508–511/523–542/256; N07/S12/S15.

The EV denominator includes only branches containing action `a`. For a hero combo with branch posterior 0.2/0.8, suppose a mapped raise exists only in the first branch, with EV +10. The specified result is `(0.2 * 10) / 0.2 = +10`, despite having no value for 80% of the posterior. A residual branch causes exactly this omission for every action. The output can consequently have EV on every listed action and receive a highest-EV headline while much of its model is unevaluated. Reporting residual probability in notes does not make that a complete action EV. For a fully evaluated action, averaging under the pre-action branch posterior is reasonable; multiplying by hero's policy frequency is not the missing repair.

Separately, branches belong to individual seats and gain evidence from that seat's actions. After villain's translated wager, hero may have taken no action: villain has two combo-dependent branches, but nothing defines how hero acquires the corresponding source-node histories or weights for hero's next lookup. Mirroring the initial translation fractions would ignore villain's observed likelihood; copying villain's per-combo posterior indexes the wrong player's cards. §13.1 tests successive actions by one seat and does not resolve this actor transition.

**Edit:** make numeric `EV(a,c)` unavailable unless that identical mapped action has a verified payoff in **every positive-posterior branch**, including any unresolved/residual mass; never normalize away missing branches. Expose known frequency mass separately from a complete action distribution and suppress a complete-menu headline when mass is unresolved. Define shared translated-history identities and advancement at every actor change, with the posterior appropriate to the receiving actor's combo. To bound phase 1, explicitly use the existing missing-continuation fallback wherever that cross-actor posterior is unavailable: retain the last justified per-seat marginals, stop descendant conditioning with reasons, and return `MissingPreflopNode` for an unavailable current lookup. A general joint multiway branch-inference engine is not a prerequisite. Add a two-actor translation example and the 0.2/0.8 missing-action example.

The following are **nonblocking follow-ups**, including those rated MAJOR for the behavior or test they affect.

**P03 — MAJOR — A newly admitted projection fixture acts out of turn.** §§10.2/13.1/13.3, L565/668/727; N02. In `A bet50, C call50, B raise150, C fold, A to act`, the first three actions establish cyclic order A→C→B. After B raises, **A**, not C, owes the next response. No seat assignment makes the complete listed sequence legal. **Edit:** use order A→B→C and `A bet50, B call50, C raise150, A raise250, B fold, C to act`. Give all three ample stacks. Projection A Bet50, C Raise150, A Raise250 is legal, preserves B's 50 as dead money, and leaves C facing100. Update both admitted-case oracles and the designated baseline case. Keep the original zero-dead-money and rejected-projection examples.

**P04 — MAJOR — The scaled-cache oracle requests a decision after betting has closed.** §§10.2/10.4/13.1, L564/584/698; N04/S09. Bet50→Call closes a HU street. On flop/turn the next state is AwaitingBoard/chance; on river it is terminal. Yet the cache exports only decision nodes of the current street, and the next street must use a fresh root and replayed ranges (§5, L370). **Edit:** test non-root scaling after **Bet50 versus Bet100** for IP, and **Check→Bet50 versus Check→Bet100** for OOP. Then append the call and next board separately to test cache-backed replay into the next street; do not require a next-street strategy hit from the old entry.

**P05 — MAJOR — The truncated snapshot oracle conditions an action whose strategy was never exported.** §§4.5/9.2/13.1, L259/533/695; N06/S15. The fixture solves at prefix `[check]`; its requested node is IP after the check. A requested-node-only export contains path `[check]`, not root `[]`, where OOP's check probability lives. Replay from root therefore stops **before** the check, contrary to the asserted retained check conditioning. **Edit:** use two explicit fixtures: requested-only `[check]` stops at root without inventing a likelihood; root-only `[]` can condition OOP's check and stops at `[check]`. The complete export still exercises check→bet73→call translation. No export-policy expansion is necessary.

**P06 — MAJOR — The new bounded deadline test assumes an unmeasured target cannot be reached.** §13.2, L718; N10/S26. R8's TURN result at 50 bp does not establish that 1 bp cannot be reached inside the new 800 ms solving allowance. A correct worker reaching target must return `ok`, contradicting an unconditional `best_so_far` assertion. **Edit:** accept `ok` iff raw exploitability meets 1 bp, otherwise a measured `best_so_far`; require the complete validated payload and bounded delivery in either case. Exercise forced BestSoFar deterministically with the fake executor/clock. Retain the no-measurement and independent engine-watchdog cases.

**P07 — MAJOR — Cache schema 3 confuses whole-tree deviations and payoff boundaries with root action topology.** §§4.6/10.4/13.1, L352/581/584/698; related to S09/S25. Two concrete corrections are needed:

- The 100/500 versus 103/515 example labels the **maximum over every node** as 0.49%, using only the first half-pot bet. Under `flop_fast_v1`, that bet/call gives turn pots 200/207; the next half-pot bets are 100/104. Their root-normalized deviation is `104/103 - 100/100 = 0.0097087`, already **0.97087%**, before examining the remaining tree. **Edit:** call 0.49% the root-action deviation and derive the reported maximum from the complete materialized list; freeze that full-tree result in T4 instead of hardcoding the root number. Similarly, MenuRounded in a cache-hit test needs specified entry and query trees; rounding one nominal 0.33 bet alone is not a cache comparison.
- Rake-cap activation does not change action kinds or ordinal paths. Check/jam trees at P=100 and stacks500/504 can have identical topology and pass the SPR/deviation thresholds, while their called-jam terminal pots are 1100/1108. With identical 5% rake/cap55.2, the first terminal is below the cap and the second above it. **Edit:** compare the terminal rake-cap predicate separately if crossings are to be rejected, as L581 promises; do not claim topology detects it. Include actor/street and terminal-versus-continuation identity in structural comparison. Keep the amended 2% SPR policy and raw accuracy filter.

**P08 — MAJOR — The new shared probability validator accepts invalid distributions.** §§4.5/10.4/13.1, L287/581/700; S22. Finite rows `[-0.1, 1.1]` sum to one and pass the declared worker/cache/lock checks. The source-bundle validator explicitly checks `[0,1]`; the new shared validator does not. **Edit:** require each probability in `[0,1]`, in addition to finite values, exact dimensions, support-mask consistency and row sums. Allow an all-zero lock row solely as the declared free-combo sentinel. Add negative and above-one rows to rejection fixtures. This is ordinary boundary-validation work, not a new architecture gate.

**P09 — MINOR — Branch cardinality and log-reach sign disagree across the new definitions.** §§8.4/9.1–9.2/13.1, L508/524/536/691/693. Prose permits at most four branches total; the type and test keep four source branches **plus** a residual. Prose accumulates the log of the applied rescaling factor; the numeric test expects the opposite sign: normalization of the T3 maximum 0.18 multiplies by 1/0.18, but the required log is `ln(0.18)`. **Edit:** settle on four source branches plus one residual throughout, and accumulate the log of the **removed maximum** (equivalently minus log of the multiplier). Keep the test's `ln(0.18)` convention.

**P10 — MINOR — The dealt-seat order includes BTN twice.** §§4.3/13.1, L202/666; N09/S30. “Non-blind seats … then BTN, SB, BB” already includes BTN in the first group. For three dealt seats it literally yields BTN→BTN→SB→BB. **Edit:** say “remaining non-button, non-blind dealt seats clockwise after BB, then BTN, SB, BB”; enumerate 3-seat BTN/SB/BB and 4-seat CO/BTN/SB/BB in the fixture. The 3–6 restriction and separate short-handed lookup mapping otherwise stand.

**P11 — MINOR — Materialized-tree scope and path representations need a precise implementation note.** §§2/4.5–4.6/9.1/10.4, L53/280–283/337–339/522/580. “Every action node of every street” could mean the abstract betting tree or the card-expanded solved game. The latter needs runout identity; ordinal action indices alone do not distinguish two turn cards. The backend supplies an abstract `ActionTree` with chance outcomes collapsed. [ActionTree contract](https://b-inary.github.io/postflop_solver/postflop_solver/struct.ActionTree.html).

**Edit:** explicitly materialize that **betting skeleton**, auto-crossing one abstract chance boundary between streets, with a street/terminal marker; reserve card expansion for the worker. Keep exports limited to current-street decision nodes. Name the wire's chip-path node type separately from ordinal-path cache/snapshot nodes, and state that ingestion resolves chip paths against the source materialized tree before cache selection or snapshot registration. This makes the existing design explicit without introducing a second solver or a card-expanded tree in the engine. Proto version 3/cache schema 3 themselves are consistent, including the v3 directory and version checks; changing illustrative representations before implementation does not require supporting earlier versions.
