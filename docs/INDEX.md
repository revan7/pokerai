## How to update this index

- Any commit that **adds** a new document, **revises** a spec/plan/design doc, or **changes the disposition** of a review/changelog (e.g., a pending item gets applied) must add or edit that document's row in this same commit — no doc change lands without an `INDEX.md` update in the same commit (`docs/CONVENTIONS.md` rule 3-4 for spec/plan revisions extends to every doc type here). The orchestrator owns this file; an implementing agent proposes the row(s) its task needs in its own report instead of editing this file directly, unless its task explicitly assigns it this file.
- A row's **status** moves from `current` to `historical, applied` (or `historical, partially applied`) only once a changelog or later revision actually disposes of its findings — not merely because a newer document exists that touches the same topic.
- Use **`superseded by <path>`** only when a document is wholesale replaced by a different file at a different path (the current in-place-revision convention — one file per spec/plan, edited and re-versioned — means no row uses this today; it will apply if that convention ever changes, e.g., a plan split into two files).
- Use **`current (pending)`** for a row that anticipates a deliverable already commissioned (named in an orientation note, a log entry, or a task brief) but not yet written as a file — this keeps the index a complete map of what's authoritative-or-coming without letting `docs/AUDIT.md` E1 flag it as a missing path. Convert it to `current` (or the appropriate disposition) in the same commit that creates the file.
- Keep the "Plan total" and "Current authorities" task/step counts in sync with the plans; recompute them from `grep -c '^\s*- \[ \]' docs/superpowers/plans/*.md` rather than trusting a changelog's stated total, since that count is easy to verify directly.
