# Plan 5: Tauri UI and E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Windows 11 PokerAI desktop application, with keyboard hand entry, honest progressive recommendations, engine-owned undo, persistent session settings, pre-solver controls, and the chart-backed Windows WebDriver acceptance test.

**Architecture:** Small React components consume a typed `Backend`; the production implementation uses Tauri 2 commands and `Channel<RecommendationEvent>`, and Vitest supplies a fake backend through `mockIPC`. A bounded command dispatcher on a dedicated standard Rust thread owns the engine handle; commands asynchronously await replies without doing engine work, disk I/O, process waits, or lock waits on the WebView or Tokio threads. The engine retains ownership of worker spawning, deadlines, cancellation, replay, legality, and pre-solving.

**Tech Stack:** Rust edition 2021, stable 1.95 or newer, MSVC; Tauri `2.11.5`, tauri-build `2.6.3`, `@tauri-apps/api` `2.11.1`, `@tauri-apps/cli` `2.11.4`; ts-rs `12.0.1`; React/ReactDOM `18.3.1`, Vite `7.3.6`, TypeScript `5.9.3`, Vitest `4.1.11`; WebdriverIO 9, `@wdio/tauri-service` `1.3.0`, tauri-driver `2.0.6`.

**Spec:** `docs/superpowers/specs/2026-09-10-pokerai-assistant-design.md`, revision 6 (amendments S1–S17 from `docs/research/REVIEW-cross-plan.md` §3, plus the §13.2 fixture correction), especially §§2, 3.1–3.6, 4.1–4.4, 5, 5.1, 6, 7, 10.5, 12, 13.4, 14.4. Also read `docs/design/2026-09-10-design-outline.md` §0b, `docs/research/R8-solver-bench.md`, `docs/research/R5-app-stack.md`, and `docs/research/REVIEW-cross-plan.md` §§1, 2, 4, 5 for the resolved engine façade. Date: 2026-09-10. This is the fifth plan; implementation begins after Plans 1–4 supply their public surfaces and chart fixtures.

## Global Constraints

- “6-max NLHE cash, manual entry, Windows 11 desktop, private use only”.
- “Rust stable 1.95 or newer.” Rust edition 2021; Node 24; Python 3.12 only for `tools/`.
- “Tauri 2 requires the MSVC target.” Use Plan 1's `rust-toolchain.toml`, channel `stable-x86_64-pc-windows-msvc`; the user confirms MSVC is installed. Do not write a second toolchain file.
- “Dependency direction is strictly downward: `proto` <- `core-*` <- `cache`/`engine` <- `bench`/`pokerai-app`.” “No crate depends on `solver-worker`.”
- “`solver-worker` is the only crate that links AGPL code”; `pokerai-app` is `MIT OR Apache-2.0`. The engine owns the worker; the shell only delegates start/stop.
- “Tauri commands never block: `recommend` enqueues and returns; results flow through `Channel<RecommendationEvent>`.” Engine threads are “std threads, never Tokio workers”; `rayon` only in the worker.
- “TypeScript types for every `proto` type are generated at build time (`ts-rs` **(spec decision)**).” Never maintain an independent handwritten domain model in TypeScript.
- “all `HandState`, worker and cache wager amounts (blinds, stacks, bets, pots) are integer chips (`u32`)”; “`cap_mchips: u32`”; `pot + stacks < 2^31`.
- “Display: `ev_bb = ev_chips / bb_chips` rounded to 0.01 bb at render time only.” `Recommendation.actions[].ev_bb` is already in bb: render it directly, without dividing again. Fold EV is 0 exactly when supplied by the engine.
- “Decision identity: `(hand_id, hand_revision, decision_id, config_revision, model_revision)`”. Every event must match all five fields; never infer identity from an event.
- “`HandConfig` is copied into `HandState` at `begin_hand`; a session `set_config` takes effect from the next hand.” Active-hand corrections require abandon and re-entry.
- “3 to 6 dealt seats are supported.” UTG straddle requires six dealt seats, fully posted, `amount_chips >= 2*bb_chips`. Two dealt seats are `FormatUnsupported{detail: "two dealt seats"}`.
- `SolverPrefs`: “threads: u8 = 16, target_bp: u16 = 50, flop_budget_s: u8 = 10 (1..=30, section 7)”. Outline §0b confirms the default 10 s.
- Final delivery: “`t0 + 15 s` for river and turn decisions” and “`t0 + 5 s + flop_budget_s` for flop decisions”; admission time excludes human entry. UI progress is coalesced to at most one update per 250 ms.
- “an `Equity` event carrying the active identity enriches whatever `Fast`/`Provisional`/`Final` is displayed, including a `Final` that arrived earlier”; “a `Ready` estimate is never replaced by a `Pending` one”.
- “Reasons accumulate across source, replay, cache and solve on every path”; an `Unsupported` result retains `partial`. The UI displays the engine's reasons without upgrading coverage.
- Experimental output is separate, labelled “experimental, not solved”; never merge its actions into the main recommendation.
- Pre-solver: no hand in progress and no request for 30 s; tier 1 is required, approximately 52 h of idle work in the measured analogue, not a launch-time operation. Pause/resume delegates to Plan 4.
- Worker commit `9d1509fe5077d019825f833eed04b16d342dfda1`; `rustflags = ["-C", "target-feature=+avx2"]` for both Windows targets; `bincode = "=2.0.0-rc.3"` and `bincode_derive = "=2.0.0-rc.3"` remain Plan 2's worker dependencies.
- Configuration: `%APPDATA%\PokerAI\config.json`; decisions: `%LOCALAPPDATA%\PokerAI\decisions.jsonl`; cache: `%LOCALAPPDATA%\PokerAI\cache\v3`. Never use Tauri's identifier-derived configuration directory in place of the specified `PokerAI` directory.
- Phase 1 ships chart bundles, `ChartRounded`, no preflop EV; V9 and the exploit slice are deferred. `set_seat_tag` returns a typed unsupported error without changing `model_revision`.
- Every task has a red/green cycle and one commit. After every task run root `cargo test --workspace`, and root `npm test` (delegates to the UI workspace); no skipped tests or committed intentionally failing tests.

Plan 4's `PresolverStatus` is a Rust struct without a `Serialize` derive today (cross-plan Or7 assigns that derive to Plan 4 Task 14); Task 3 of this plan still projects its documented fields to JSON by hand so this plan does not block on Plan 4's schedule.

```rust
// Required from Plan 2 (binding; land before this plan's Task 2 compiles against `engine`).
// EngineError, core_model::BeginHand and PresolverStatus are upstream types.
Engine::new(config: GameConfig, paths: Paths) -> Result<(Engine, Vec<String>), EngineError>;
// ^ the Vec<String> is startup diagnostics (bundle quarantine, missing-AVX2 banner; spec §12/§3.7).
//   Plan 2's first draft returns a bare `Result<Engine, EngineError>` with no warning channel (BL-6);
//   success must still be able to carry non-fatal warnings.
Engine::set_config(&mut self, config: GameConfig) -> Result<u32, EngineError>;
// ^ cross-plan M10/S15: Plan 2's first draft returns a bare `u32`, which cannot reject
//   `flop_budget_s == 31` (spec §13.3 `flop_budget_setting_golden`). This plan already assumed
//   the fallible form; no Task 2 code changes for this entry.
Engine::shutdown(&mut self);
// ^ cross-plan M11: by mutable reference with an internal idempotent flag, not `shutdown(self)`.
//   Tauri's managed `State<'_, Service>` never owns the `Engine` by value, so a by-value method is
//   uncallable from inside the dispatcher thread; this plan already assumed `&mut self`.
Engine::set_hero_cards(&mut self, cards: [Card; 2]) -> Result<HandState, EngineError>;
// ^ cross-plan M14/Or3 (= REVIEW-of-plan-5 BL-3): absent from Plan 2's first draft entirely. Wraps
//   `core_model::set_hero_cards`, bumping `hand_revision` through `IdentityState::mutate()` exactly
//   like `apply_action`/`set_board` (spec §5 step 3), so descendant decision identities invalidate.
Engine::presolver_status(&self) -> cache::presolver::PresolverStatus;
Engine::presolver_pause(&mut self);
Engine::presolver_resume(&mut self);
// ^ REVIEW-of-plan-5 MA-12: Plan 4 promises only delegation, not these signatures. `&self` suffices
//   for `presolver_status` because `EnginePort::dispatch` already holds `&mut Engine`.
Paths { worker: PathBuf, preflop: PathBuf, cache: PathBuf, log: PathBuf }
// ^ cross-plan M13/Or5: Plan 2's first draft has only two fields (`log_dir`, `worker_exe`); this
//   plan's four-field shape is the one M13 fixes Plan 2 to produce. Plan 3 populates `preflop`
//   (chart-bundle directory), Plan 4 reads `cache`. No Task 3 code changes for this entry.

// Unchanged from Plan 2's produced API — cited so Task 2's `Op` arms match it verbatim.
Engine::begin_hand(&mut self, begin: core_model::BeginHand) -> Result<HandState, EngineError>;
Engine::apply_action(&mut self, action: Action) -> Result<HandState, EngineError>;
Engine::set_board(&mut self, board: &[Card]) -> Result<HandState, EngineError>;
Engine::undo(&mut self) -> Result<HandState, EngineError>;
Engine::recommend(&mut self, sink: Box<dyn EventSink>) -> Result<DecisionIdentity, EngineError>;
// ^ cross-plan M12 (consumer-side: this plan changes, not Plan 2): no `+ Send` at the call site.
//   `pub trait EventSink: Send` already carries the bound as a supertrait; `dyn EventSink` and
//   `dyn EventSink + Send` are distinct trait-object types even though every `EventSink` is `Send`.
Engine::cancel(&mut self, decision_id: u64);
Engine::finish_hand(&mut self);
Engine::abandon_hand(&mut self);
trait EventSink: Send { fn emit(&mut self, event: RecommendationEvent); }
```

Plan 1's concrete serde declarations are authoritative: `Card` is a two-character string (`"As"`); `Seat` is numeric; `Street` and recommendation `Phase` are lowercase; `HandPhase` has a `phase` tag (`{phase:'betting',street:'flop'}`); `Rake` has a snake-case `kind`; coverage/reasons/availability/events have PascalCase `kind`. A Final is `{kind:'Final', ...recommendation}`. `Action::AllIn` serializes as `allin`, while `LegalAction::AllIn` is `all_in`. Derived's six-element vectors use the physical seat number as index, including undealt seats. HandState.stacks_start and admission stacks instead follow dealt-seat order. Task 1 preserves these serde attributes and proves them with witnesses.

struct Registry { cfg: Config, declarations: BTreeMap<String, String> }

#[derive(Debug, thiserror::Error, Serialize)]
#[serde(tag = "type", content = "detail")]
pub enum AppError {

    #[error("command queue is full")] Busy,
    #[error("application is stopping")] Closed,
    #[error("serialization: {message}")] Serialization { message: String },

use std::sync::{mpsc, Arc, atomic::{AtomicBool, Ordering}};
use tauri::ipc::Channel;
pub enum Op {
    Config(GameConfig), Begin(BeginHand), Hero([Card; 2]), Action(Action), Board(Vec<Card>),
    Undo, Recommend(Channel<RecommendationEvent>), Cancel(u64), Finish, Abandon,
    PresolverStatus, Pause, Resume,
}
impl Op {
    pub fn name(&self) -> &'static str { match self {
        Self::Config(_) => "set_game_config", Self::Begin(_) => "begin_hand",
        Self::Hero(_) => "set_hero_cards", Self::Action(_) => "apply_action",
        Self::Board(_) => "set_board", Self::Undo => "undo", Self::Recommend(_) => "recommend",
        Self::Cancel(_) => "cancel", Self::Finish => "finish_hand", Self::Abandon => "abandon_hand",
        Self::PresolverStatus => "presolver_status", Self::Pause => "presolver_pause",
        Self::Resume => "presolver_resume" } }
}
pub trait EnginePort: Send + 'static {
    fn dispatch(&mut self, op: Op) -> Result<Value, AppError>;
    fn shutdown(&mut self);
}
type Reply = futures_channel::oneshot::Sender<Result<Value, AppError>>;
#[derive(Clone)]
pub struct Service {
    tx: mpsc::SyncSender<(Op, Reply)>, stop: Arc<AtomicBool>, done: Arc<AtomicBool>,
}
impl Service {
    pub fn spawn(mut port: Box<dyn EnginePort>) -> Self {
        let (tx, rx) = mpsc::sync_channel::<(Op, Reply)>(32);
        let stop = Arc::new(AtomicBool::new(false));
        let done = Arc::new(AtomicBool::new(false));
        let (s, d) = (stop.clone(), done.clone());
        std::thread::Builder::new().name("app-dispatch".into()).spawn(move || {
            while !s.load(Ordering::Acquire) {
                match rx.recv_timeout(std::time::Duration::from_millis(20)) {
                    Ok((op, reply)) => { let _ = reply.send(port.dispatch(op)); }
                    Err(mpsc::RecvTimeoutError::Timeout) => {}
                    Err(mpsc::RecvTimeoutError::Disconnected) => break,
                }
            }
            while let Ok((_, reply)) = rx.try_recv() { let _ = reply.send(Err(AppError::Closed)); }
            port.shutdown();
            d.store(true, Ordering::Release);
        }).expect("app-dispatch thread");
        Self { tx, stop, done }
    }
    pub async fn request<T: DeserializeOwned>(&self, op: Op) -> Result<T, AppError> {
        if self.stop.load(Ordering::Acquire) { return Err(AppError::Closed); }
        let (tx, rx) = futures_channel::oneshot::channel();
        self.tx.try_send((op, tx)).map_err(|e| match e {
            mpsc::TrySendError::Full(_) => AppError::Busy,
            mpsc::TrySendError::Disconnected(_) => AppError::Closed })?;
        Ok(serde_json::from_value(rx.await.map_err(|_| AppError::Closed)??)?)
    }
    pub fn stop(&self) { self.stop.store(true, Ordering::Release); }
    pub fn stopped(&self) -> bool { self.done.load(Ordering::Acquire) }
}

// service.rs additions
pub struct EngineAdapter {
    pub engine: engine::Engine,
    pub accepted_config: Box<dyn FnMut(GameConfig) + Send>,
    pub on_shutdown: Box<dyn FnMut() + Send>,
}
fn encode<T: serde::Serialize>(v: T) -> Result<Value, AppError> { Ok(serde_json::to_value(v)?) }
pub(crate) fn encode_hand(h: HandState) -> Result<Value, AppError> {
    if h.hand_id>MAX_SAFE_ID { return Err(AppError::Engine {message:"hand ID exceeds JSON safe integer range".into()}); }
    encode(h)
}
fn engine_error(e: engine::EngineError) -> AppError { AppError::Engine { message: e.to_string() } }
const MAX_SAFE_ID: u64 = 9_007_199_254_740_991;
pub(crate) fn safe_identity(id: &DecisionIdentity) -> Result<(), AppError> {
    if id.hand_id > MAX_SAFE_ID || id.decision_id > MAX_SAFE_ID {
        return Err(AppError::Engine { message: "identity exceeds JSON safe integer range".into() });
    }
    Ok(())
}
// MAX_SAFE_ID/safe_identity are boundary assertions, not a feature: Plan 2's IdentityState counters
// start at 1 and increment, so in practice this can never fire before u64 itself would overflow (MI-6).
struct ChannelSink(Channel<RecommendationEvent>);
impl engine::EventSink for ChannelSink {
    fn emit(&mut self, event: RecommendationEvent) {
        let id = match &event {
            RecommendationEvent::Fast(r) | RecommendationEvent::Provisional(r) |
            RecommendationEvent::Final(r) => &r.identity,
            RecommendationEvent::Equity { identity, .. } |
            RecommendationEvent::Progress { identity, .. } |
            RecommendationEvent::NoDecision { identity, .. } => identity,
        };
        // Dropping an event here is unreachable in production (MI-6/MI-7): it would require an
        // identity past MAX_SAFE_ID, which Plan 2's monotonic counters cannot reach in practice.
        if safe_identity(id).is_ok() { let _ = self.0.send(event); }
        // A closed channel never panics or stops the engine/watchdog.
        // The engine owns this sink until equity completes, including after Final.
    }
}
impl EnginePort for EngineAdapter {
    fn dispatch(&mut self, op: Op) -> Result<Value, AppError> {
        let e = &mut self.engine;
        match op {
            Op::Config(mut c) => {
                c.config_revision = e.set_config(c.clone()).map_err(engine_error)?;
                (self.accepted_config)(c.clone()); encode(c)
            }
            Op::Begin(b) => {
                // proto::BeginHand -> core_model::BeginHand (cross-plan review M6/Or4: Plan 1 now
                // owns the ID-free DTO; Plan 2's Engine::begin_hand is unchanged and still takes
                // the engine-internal type, which carries the assigned hand_id/stacks_start).
                // Engine::begin_hand overwrites hand_id from its own counter
                // (IdentityState::begin_hand()); 0 is a placeholder the shell never observes.
                let core = core_model::BeginHand { hand_id: 0, button: b.button, hero: b.hero,
                    dealt: b.dealt, stacks_start: b.stacks, hero_cards: b.hero_cards };
                encode_hand(e.begin_hand(core).map_err(engine_error)?)
            }
            Op::Hero(c) => encode_hand(e.set_hero_cards(c).map_err(engine_error)?),
            Op::Action(a) => encode_hand(e.apply_action(a).map_err(engine_error)?),
            Op::Board(b) => encode_hand(e.set_board(&b).map_err(engine_error)?),
            Op::Undo => encode_hand(e.undo().map_err(engine_error)?),
            Op::Recommend(c) => {
                // Engine::recommend takes `Box<dyn EventSink>` (cross-plan M12): EventSink already
                // carries `Send` as a supertrait, so no `+ Send` is written at this call site.
                let id = e.recommend(Box::new(ChannelSink(c))).map_err(engine_error)?;
                safe_identity(&id)?; encode(id)
            }
            Op::Cancel(id) => { e.cancel(id); encode(()) }
            Op::Finish => { e.finish_hand(); encode(()) }
            Op::Abandon => { e.abandon_hand(); encode(()) }
            Op::PresolverStatus => {
                let s=e.presolver_status();
                encode(serde_json::json!({"paused":s.paused,"running":s.running,"pending":s.pending,
                    "done":s.done,"failed":s.failed,"tier_done":s.tier_done,"tier_total":s.tier_total,
                    "measured_p50_s":s.measured_p50_s,"estimated_remaining_s":s.estimated_remaining_s,
                    "scenario_hits":s.scenario_hits}))
            },
            Op::Pause => { e.presolver_pause(); encode(()) }
            Op::Resume => { e.presolver_resume(); encode(()) }
        }
    }
    fn shutdown(&mut self) {
        // Engine::shutdown(&mut self) is idempotent (cross-plan M11); no Option<Engine> dance needed.
        self.engine.shutdown();
        self.accepted_config=Box::new(|_|{}); // Disconnect writer before joining it.
        (self.on_shutdown)();
    }
}

pub fn exit_requested(app: &tauri::AppHandle, api: &tauri::ExitRequestApi) {
    let Some(service) = app.try_state::<crate::service::Service>() else { return; };

struct GatedPort { started: Option<std::sync::mpsc::Sender<()>>,
    gate: Arc<(Mutex<bool>, std::sync::Condvar)>, shutdowns: Arc<Mutex<u32>> }
impl service::EnginePort for GatedPort {
    fn dispatch(&mut self, _: service::Op) -> Result<Value, error::AppError> {
        if let Some(tx) = self.started.take() {
            tx.send(()).unwrap();
            let (lock, cv) = &*self.gate; let ready = lock.lock().unwrap();
            drop(cv.wait_while(ready, |ready| !*ready).unwrap());
        }
        Ok(Value::Null)
    }
    fn shutdown(&mut self) { *self.shutdowns.lock().unwrap() += 1; }
}
#[test]
fn stop_is_idempotent_while_a_request_is_in_flight() {
    let gate = Arc::new((Mutex::new(false), std::sync::Condvar::new()));
    let (tx, rx) = std::sync::mpsc::channel();
    let shutdowns = Arc::new(Mutex::new(0u32));
    let service = service::Service::spawn(Box::new(GatedPort {
        started: Some(tx), gate: gate.clone(), shutdowns: shutdowns.clone() }));
    let held = service.clone();
    let worker = std::thread::spawn(move ||
        tauri::async_runtime::block_on(held.request::<Value>(service::Op::PresolverStatus)));
    rx.recv_timeout(std::time::Duration::from_secs(1)).unwrap(); // request is now parked in dispatch
    service.stop(); service.stop(); // signal close twice while the port is still busy
    *gate.0.lock().unwrap() = true; gate.1.notify_one(); // release the held request
    let _ = worker.join().unwrap();
    let deadline = std::time::Instant::now() + std::time::Duration::from_secs(1);
    while !service.stopped() && std::time::Instant::now() < deadline { std::thread::yield_now(); }
    assert!(service.stopped());
    assert_eq!(*shutdowns.lock().unwrap(), 1);
}

  EquityEstimate, Seat, HandState } from '../ipc/types.gen';
type Progress = Extract<RecommendationEvent,{kind:'Progress'}>;
export type DisplayState = { active: DecisionIdentity|null; recommendation:Recommendation|null;
  equity:EquitySummary; progress:Progress|null; noDecision:string|null;
  requestedAt:number|null; finalAt:number|null };

const initial = (): DisplayState => ({active:null,recommendation:null,equity:empty(),
  progress:null,noDecision:null,requestedAt:null,finalAt:null});
export function sameIdentity(a:DecisionIdentity|null,b:DecisionIdentity):boolean {
  return a !== null && a.hand_id===b.hand_id && a.hand_revision===b.hand_revision &&
    a.decision_id===b.decision_id && a.config_revision===b.config_revision && a.model_revision===b.model_revision;
}
function estimate(a:EquityEstimate|undefined,b:EquityEstimate):EquityEstimate {
  // MI-8: only guards Ready against a later Pending, not against Unavailable — spec §4.4 promises
  // "a Ready estimate is never replaced by a Pending one" and the engine emits at most one Ready
  // per population, so this narrower guard is literal-correct and deliberate, not an omission.
  return a?.availability.kind==='Ready' && b.availability.kind==='Pending' ? a : b;
}
function rows(a:Array<[Seat,EquityEstimate]>,b:Array<[Seat,EquityEstimate]>):Array<[Seat,EquityEstimate]> {
  const result = new Map(a); for (const [seat,value] of b) result.set(seat,estimate(result.get(seat),value));
  return [...result];
}
export function mergeEquity(a:EquitySummary,b:EquitySummary):EquitySummary {
  const pots = new Map(a.per_pot_shares.map(p => [p.pot_index,p]));
  for (const p of b.per_pot_shares) pots.set(p.pot_index,{...p,shares:rows(pots.get(p.pot_index)?.shares??[],p.shares)});
  return {hero_combo_vs_each:rows(a.hero_combo_vs_each,b.hero_combo_vs_each),
    hero_range_vs_each:rows(a.hero_range_vs_each,b.hero_range_vs_each),per_pot_shares:[...pots.values()]};
}
function eventIdentity(e:RecommendationEvent):DecisionIdentity { return e.identity; }

export class Recommendations {
  private value = initial(); private generation=0;
  private listeners = new Set<() => void>();
  private timer:ReturnType<typeof setTimeout>|null=null;
  private pendingProgress:Progress|null=null;
  constructor(private backend:Backend,private error:(e:unknown)=>void) {}
  snapshot = ():DisplayState => this.value;
  subscribe = (listener:()=>void) => { this.listeners.add(listener); return () => {this.listeners.delete(listener);}; };
  private publish() { for (const listener of this.listeners) listener(); }
  invalidate() {
    const old=this.value.active; this.generation++;
    if(this.timer!==null) clearTimeout(this.timer); this.timer=null; this.pendingProgress=null;
    this.value=initial(); this.publish();
    if(old) void this.backend.cancel(old.decision_id).catch(this.error);
  }
  async request(hand:HandState) {
    this.invalidate(); const generation=this.generation;
    const early:RecommendationEvent[]=[]; let admitted=false;
    this.value={...this.value,requestedAt:performance.now()}; this.publish();
    try {
      const id=await this.backend.recommend(event => {
        if(generation!==this.generation) return;
        if(!admitted) {
          if(event.kind==='Progress') {
            const old=early.findIndex(e=>e.kind==='Progress'); if(old>=0) early.splice(old,1);
          }
          early.push(event); return;
        }
        this.accept(event);
      });
      if(generation!==this.generation) { await this.backend.cancel(id.decision_id); return; }
      // MA-8: config_revision is deliberately excluded here. Spec §4.2/§12: a session
      // set_game_config bumps the session's config_revision, but HandConfig is frozen into the
      // hand at begin_hand and keeps the old value until the next hand. A mid-hand save would
      // otherwise make id.config_revision (from the engine's live session config) permanently
      // mismatch hand.config.config_revision (frozen), throwing on every subsequent request for
      // the rest of the hand. The five-field sameIdentity() check on individual *events* in
      // accept() below still guards against ever rendering the wrong decision.
      if(id.hand_id!==hand.hand_id || id.hand_revision!==hand.hand_revision) {
        await this.backend.cancel(id.decision_id); throw new Error('Admission identity does not match the active hand');
      }
      this.value={...this.value,active:id}; admitted=true;
      for(const event of early) this.accept(event); this.publish();
    } catch(e) { if(generation===this.generation) {this.invalidate();this.error(e);} }
  }
  accept(event:RecommendationEvent) {
    if(!sameIdentity(this.value.active,eventIdentity(event))) return;
    if(event.kind==='NoDecision') {
      if(this.timer!==null)clearTimeout(this.timer);this.timer=null;this.pendingProgress=null;
      this.value={...this.value,recommendation:null,noDecision:event.reason,progress:null};
    } else if(event.kind==='Equity') {
      const equity=mergeEquity(this.value.equity,event.equity);
      this.value={...this.value,equity,recommendation:this.value.recommendation ?
        {...this.value.recommendation,equity}:null};
    } else if(event.kind==='Progress') {
      if(this.value.recommendation?.phase==='final' || this.value.noDecision!==null) return;
      this.pendingProgress=event;
      // MI-9: trailing-edge throttle — the first Progress in a burst is itself delayed up to
      // 250 ms, not shown immediately and then throttled. Spec §7 says "at most every 250 ms",
      // which a trailing-edge throttle satisfies; this is a deliberate simplicity choice over a
      // leading-edge throttle, which would show the very first progress tick sooner.
      if(this.timer===null) this.timer=setTimeout(()=>{
        this.timer=null;const p=this.pendingProgress;this.pendingProgress=null;
        if(p && sameIdentity(this.value.active,p.identity)) {this.value={...this.value,progress:p};this.publish();}
      },250);
      return;
    } else {
      if(this.value.noDecision!==null)return;
      const rec:Recommendation=event;
      const current=this.value.recommendation;
      if(current && rank[rec.phase]<rank[current.phase]) return;
      const equity=mergeEquity(this.value.equity,rec.equity);
      if(rec.phase==='final') {
        if(this.timer!==null) clearTimeout(this.timer);this.timer=null;this.pendingProgress=null;
      }
      this.value={...this.value,recommendation:{...rec,equity},equity,noDecision:null,
        progress:rec.phase==='final'?null:this.value.progress,
        finalAt:rec.phase==='final'?(this.value.finalAt??performance.now()):this.value.finalAt};
    }
    this.publish();
  }
  dispose() { this.invalidate(); this.listeners.clear(); }
}

import type {Action,HandState} from '../ipc/types.gen';
export function actionForKey(h:HandState|null,key:string):Action|null {
  if(!h||h.phase.phase!=='betting'||h.derived.to_act===null)return null;
  const legal=h.derived.legal;
  if(key==='F'&&legal.some(a=>a.kind==='fold'))return {kind:'fold'};
  if(key==='C'){
    if(legal.some(a=>a.kind==='check'))return {kind:'check'};
    if(legal.some(a=>a.kind==='call'))return {kind:'call'};
  }
  if(key==='A'){const allin=legal.find(a=>a.kind==='all_in');if(allin?.kind==='all_in')return {kind:'allin',to:allin.to};}
  return null;
}

  return !!h&&h.phase.phase==='betting'&&h.derived.to_act!==null&&
    h.derived.legal.some(a=>a.kind==='bet'||a.kind==='raise');
}

  if(!Number.isInteger(to)||to<0||to>4_294_967_295)throw new Error('Enter whole chips');

        // on each pair keeps the tuple type, and the explicit annotation catches any further drift.
        const defaults:StackDrafts={...Object.fromEntries(

      // returns for every 'H' that could reach this switch (mode/text conditions are otherwise
      // guaranteed by the branches above it), so a second case is unreachable dead code.
      case 'B':if(canWager(h))this.update({mode:'bet',text:'',error:null});return;
      case ' ':if(h&&decisionReason(h)===null)void this.rec.request(h);return;
      case 'T':if(h?.derived.to_act!==null&&h?.derived.to_act!==undefined)this.update({mode:'tag',tagSeat:h.derived.to_act});return;
    }

  }

  const handler=(event:KeyboardEvent)=>{
    if(event.repeat||event.isComposing||event.altKey||event.metaKey)return;
